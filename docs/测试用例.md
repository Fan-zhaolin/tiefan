# 验收用例（30 条）

> 文件：`tests/fixtures/acceptance.yaml`
> **这 30 条全绿是 v0 的发布门槛。** 任何一条红，不算完成。

---

## 1. Fixture 格式

```yaml
- id: "01"
  input: "鸡胸200g 米饭一碗"
  expect:
    foods: [鸡胸, 米饭]        # 按顺序必须解析出这些食物（name 或 alias 命中即可）
    unresolved: 0              # unresolved 条目数，默认 0
    must_be_exact: [鸡胸]       # 这些条目必须 confidence = exact
    kcal: null                 # 精确值，严格相等；null = 不校验
    kcal_range: [480, 540]     # 区间包含；null = 不校验
```

字段全部可选，只校验写了的项。

---

## 2. 通过标准

```
30 条中 ≥ 28 条通过，且 #07 三杯鸡、#22 八宝粥 必须通过。
```

**这两条是硬的**：数字菜名被解析成数量，是最典型的翻车，一旦发生整条解析链的可信度归零。

## 4. 额外必测（不在 30 条内，但要写单测）

| 场景 | 要求 |
|---|---|
| 超长输入（10,000 字） | 不抛异常，< 50ms 返回 |
| 纯 emoji | 不抛异常 |
| 重复同一食物两次（`鸡蛋2个 鸡蛋1个`） | 合并或两条都要，不许丢 |
| `0g` / `负数` / `9999999g` | 不崩，超上界走 L4 |
| 同时含 `三杯鸡` 和 `鸡胸200g` | 前者整词命中，后者正常解析 |
