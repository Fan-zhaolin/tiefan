# 03 · 架构与边界

## 1. 为什么是单仓 + 多包

一个 `packages/core` 同时被 CLI 和浏览器 import。**这是本项目唯一的架构收益，不许破坏。**

不给 monorepo 里放一份 `src/`：Web 打包会把 CLI 的 argv 代码拖进去。

---

## 2. core 的边界（最容易被破坏的一条）

```ts
// 允许
import { parseMeal } from '@meal/core'

// 禁止 —— CI 会失败
import fs from 'node:fs'
import path from 'node:path'
import { readFile } from 'fs/promises'
document.querySelector(...)
window.location
```

**enforce 方式**：`packages/core/eslint.config.js`

```js
rules: {
  'no-restricted-imports': ['error', {
    patterns: ['node:*', 'fs', 'path', 'os', 'child_process']
  }],
  'no-restricted-globals': ['error', 'window', 'document', 'localStorage', 'fetch']
}
```

CI 里跑 `pnpm lint`，失败即阻断。

> `fetch` 也禁——网络只能通过注入的 `LlmClient`（v0 不用）。

---

## 3. 依赖注入的唯一形式

```ts
export interface DataSet {
  dishes: Dish[]
  units: Unit[]
  methods: Method[]
}

// v0 唯一出口
export function parseMeal(raw: string, data: DataSet): MealResult

// v0.1 才加
export interface LlmClient {
  extract(raw: string): Promise<Array<{ span: string; food: string; qty: number | null; unit: string | null }>>
}
export function parseMealWithLlm(raw: string, data: DataSet, llm: LlmClient): Promise<MealResult>
```

**v0 不要实现 `LlmClient`。** 只把类型留好。

---

## 4. 数据流

```
packages/data/dishes/*.yaml
        │  build
        ▼
packages/data/dist/data.json
        │
        ├──► packages/cli   （构建时内联）
        └──► packages/web   （构建时内联）
                    │
                    ▼
              parseMeal(raw, data)
```

**Web 端不要运行时 fetch 外部 CDN。** data.json 构建时内联进单文件 HTML。

## 6. 构建与分发

### CLI

```bash
# 开发
pnpm --filter @meal/cli dev -- "鸡胸200g 米饭一碗"

# 发布（v0）
npx @meal/cli "鸡胸200g 米饭一碗"

# 发布（v0.2，单文件二进制）
bun build --compile packages/cli/src/index.ts --outfile dist/meal
```

不用 brew：三平台维护成本 > 收益。

### Web

```bash
pnpm --filter @meal/web build   # 产出单个 index.html（约 100KB）
```

- **桌面**：双击 `dist/index.html` 可开（Chrome / Edge）。Safari 在 `file://` 下可能拒绝 `localStorage`，此时改用 Chrome 或起本地服务。
- **手机**：`file://` 无法「添加到主屏幕」，必须通过 http(s) 访问。v0 部署方式是把 `dist/` 丢到任意静态托管（GitHub Pages / Vercel），拿到 https 链接后在手机浏览器打开 → 添加到主屏幕。

**不要引入 Vite / React / 任何框架。** 单文件 + 原生 DOM。

## 7. 存储

| 端 | 存储 | 格式 |
|---|---|---|
| Web | `localStorage` | JSON 数组，按日期分 key：`meal:2026-10-27` |
| CLI | `~/.meal/YYYY-MM-DD.jsonl` | 一行一条 |

**必须是可读文本。** 不存 SQLite、不存二进制。

CLI 的 JSONL 是「原始输入日志」，不是结果快照。每行只保留时间与输入：

```json
{"t":"12:40","raw":"鸡胸200g 米饭一碗"}
```

`meal today` 每次都按当前食物库重新解析 `raw`，不采信旧日志中可能存在的营养字段；更新食物库后，同一段原文的计算结果可能变化。所以要算数请先跑 `meal today`，不要直接拿 JSONL 里的数字作统计。

Web 也保存 `t/raw`；用户选择份量时，仅附加选中的单位与已收起提示的条目编号，启动后仍按当前内联食物库重新计算，不存营养结果快照。

**导出**：`meal export > backup.jsonl`，必须有。

## 8. CI 三个 workflow，用 paths 隔离

```yaml
# .github/workflows/data.yml
on:
  pull_request:
    paths: ['packages/data/**', 'tests/fixtures/**']
# 只跑 pnpm validate + 语料回归

# .github/workflows/impl.yml
on:
  pull_request:
    paths: ['packages/core/**', 'packages/cli/**', 'packages/web/**']
# 只跑 lint + test + build

# .github/workflows/spec.yml
on:
  pull_request:
    paths: ['docs/**']
# 只跑 markdown lint
```

**为什么必须隔离**：数据 PR 不该跑 impl 测试。50 个 PR 同时来的时候，这决定了会不会崩。

## 9. 版本号（三层独立）

| 层 | 版本 | 频率 |
|---|---|---|
| 数据 | `data-v2026.10`（日历版） | 每月 1 号自动 tag |
| 实现 | `v0.3.0`（语义化） | 有实质改动才发 |
| 规格 | `spec-v1.1`（语义化，需 RFC） | 一年 1–2 次 |

**不要混成一个版本号。** 会导致版本通胀，且用户被无意义发版打扰。

## 11. 性能目标

| 场景 | 目标 |
|---|---|
| `parseMeal` 单次 | < 5ms（纯内存） |
| core 打包体积 | < 30KB gzip |
| data.json（30 条） | < 20KB |
| data.json（300 条） | < 200KB |
| 单文件 Web 总计 | < 150KB |

`parseMeal` 不许有任何 IO。它是纯函数。
