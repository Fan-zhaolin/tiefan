# T3 · 字典匹配（L2）

先读：`AGENTS.md`、`docs/02-解析与交互.md` §4.4、`docs/01-数据模型.md`

## 目标

把文本里的食物名匹配到 `dish.id`。**这是全项目最容易出错的一层。**

## 要做

### 1. `packages/core/src/parse/dict.ts`

```ts
export interface Match {
  foodId: string
  foodName: string
  span: string      // 命中原文
  start: number
  end: number
}

export function buildDict(data: DataSet): Dict
export function matchAll(text: string, dict: Dict): Match[]
```

### 2. 匹配算法

**最长匹配优先。** 把所有 `name` + `aliases` 建成按长度降序的列表，从头扫描，命中后跳过该段。

不要用分词、不要用正则回溯、不要用模糊匹配。

**规则：**

1. 精确匹配（name 或 alias）
2. 匹配是**贪心 + 最长**，不是全部候选
3. 大小写不敏感（对英文别名）
4. 空白归一后再匹配（`番茄 炒蛋` 与 `番茄炒蛋` 等价——实现方式：把待匹配文本的空格剥离，同时维护 offset 映射）

### 3. 核心难点：数字菜名整词保护

`三杯鸡`、`八宝粥`、`夫妻肺片`、`四喜丸子`、`二锅头` 这类名字里带数字。

**顺序必须是：先字典匹配，再数字解析。**

推荐做法：`parseMeal` 的执行顺序是

```
normalize → dict.matchAll → 对未命中的区间跑 rules.extractSegments
```

这样 `三杯鸡` 会先被整词吃掉，剩下的文本才交给 L1，永远不会被切成「鸡 3 杯」。

> **如果实现成先跑 rules 再匹配字典，这条必错。请严格按上面顺序。**

### 4. 别名唯一性

`buildDict` 时如果发现同一 alias 映射到两个 `id`，**直接抛错**（数据集本身有问题，应在 `pnpm validate` 阶段拦住，这里兜底）。

### 5. 单测 `packages/core/src/parse/dict.test.ts`

必须包含：

```
"三杯鸡"            → [三杯鸡]，且没有任何 Segment 产生
"八宝粥"            → [八宝粥]
"夫妻肺片"          → [夫妻肺片]
"宫爆鸡丁"          → [宫保鸡丁]（别名）
"西红柿炒鸡蛋"      → [番茄炒蛋]（别名）
"番茄 炒蛋"         → [番茄炒蛋]（空格归一）
"鸡胸200g 三杯鸡"   → [鸡胸, 三杯鸡] 两个
"黄焖鸡米饭"        → [黄焖鸡米饭]（若字典有长名，取最长）
```

## 不要做

- ❌ 不装任何分词库
- ❌ 不做拼音匹配（v0）
- ❌ 不做编辑距离容错（v0）
- ❌ 不做同义词推导（别名是人工录入的）

## 验收

```bash
pnpm test

```
